# 报告内容

视觉在 `templates/report.css`，章节和列由 `scripts/render-report.py` 固定。数据稿格式见 `docs/report-data.md`。下面是每一块必须出现的内容。查询没回来的块保留标题，正文写「未取得」，不补数字。

## 页头

标题 `{supplier_id} {供应商名称} 供应商分析报告`。口径条两行：

数据范围 `{start} ~ {用户结束日}` · 创建时间口径 · Confirm + Cancel（含当天取消）· Rebook = 1 · Overseas API

报告生成于 `{今天}` · 金额为 CNY

## 介绍

### 资源优势

三张 `.card`：市场、品牌、壁垒。三张卡都从后面的「酒店资源维度分析」归纳，用口语说判断，不复述判定公式。

- 市场：看资源优势方里达标的国家，有几个就写几个，不要只写自身 TTV 最高的那一国。点出谁的市场份额最高；自身产量最大的国家如果也达标，补一句它占自身 TTV 的比例。没有达标国家时，写产量最高的国家占自身的比例，并写明前十个国家都没有达到阈值。
- 品牌：看资源优势方里达标的集团。Independent 是独立酒店，不是集团，不写进这张卡。点出市场份额最高的一两家并写出比例，其余用「另外 N 个集团也过了阈值」带过。没有达标集团时写明前十个集团都没有达到阈值，不用 Independent 充数。
- 壁垒：看独家和优势的家数、BKS、占本供应商 BKS 的比例，直接说壁垒在哪一边。阈值留在下面表格的说明里，这张卡不重复公式。

`.oneline` 一句，与三张卡一致，点出达标的国家和品牌，不把 Independent 写成品牌。

### 资源质量

`.tag` 文字：近 30 天参考值 · 全业务线 · 不随报告时间变化。

供应商合计一行三指标，列：指标、分子、分母、比率。

| 指标 | 分子 | 分母 | 比率 |
|---|---|---|---|
| 有价率 | avail_search_ss | total_search_ss | 分子 / 分母 |
| 准确率 | rp − issue_rp | rp | 1 − issue_rp / rp |
| 失败率 | failed_bks | bks | 分子 / 分母 |

分母为 0 则比率留空。表注写明三个公式，并写失败率按向供应商下单的每次尝试计，与 ORD_0112 不同，窗口是 T-29 到 T-1。

HTML 只有这一张合计表。分账号的分子分母按 total_search_ss 降序进 Excel 的「技术指标」sheet，不在 HTML 再放第二张表。

### L2L

`.tag`：截至 `{查询日}` 的当前普通配置 · 不含客户特殊配置。

先一句摘要，再一张等级表。同一规则的相邻等级合并成一行。摘要只用这些说法：

- 供应商状态 ALLOW_ALL：该等级全部可售
- ALLOW_NO_SUPPLIER_CONFIG：供应商未配置，普通 L2L 默认全卖
- BLOCK_MISSING_LEVEL：该等级未配置，普通 L2L 不卖
- CHECK_ACCOUNT_RULES：按账号规则。国家列表照写代码；酒店列表写家数，不展开 ID；`is_allow_sell = 0` 写关闭；`margin > 0` 写加价 N% 出售；空范围且可售的兜底写其余可售

HTML 只放等级摘要，不放规则原文，也不用 `<details>`。规则原文放不进摘要时写「规则原文过长，未逐条展开」，不能自行截断。

## 整体结论

四个 `.kpi`：总 TTV（CNY）、总 BKS、有产酒店、整体 ADR。TTV 满 100 万写 `¥45.5M` 这种一位小数，不满写千分位整数。

`.verdict` 里 `.lead` 只留一句：自身产量最高的国家，加上资源优势方里市场份额最高的集团。不写 Independent。没有达标集团时，这句只写国家。下面至多两句，一句客户，一句预订模式。没有客户数据就去掉客户那句。

## 酒店资源

每块都有 `.oneline` 和表。

| 块 | 列 | 排序 |
|---|---|---|
| 独家 | 家数、BKS、占本供应商 BKS | |
| 优势 | 家数；Top 10 另表：排名、酒店 ID、酒店名、国家、集团、星级、BKS、第二名、第二名 BKS、倍数 | BKS 降序 |
| 资源优势方 | 一张表：类型、资源、本供应商 TTV 占比、其他供应商占比。类型只会出现国家优势资源、品牌优势资源、国家内品牌优势资源 | 只列占比 ≥ 阈值的资源，类型内按占比降序 |
| 集团 | 集团、酒店数、BKS、TTV、ADR、TTV 占比。一行一个，报告 Top 10 | TTV 降序 |
| 星级 / 国家 | 维度、酒店数、BKS、TTV、ADR、TTV 占比。国家一行一个，最多 10 行 | 星级 5→Unrated，国家 TTV 降序 |
| 城市 | 同上，报告 Top 15，一行一个 | TTV 降序 |

独家、优势固定是汇总句加 Top 10 表，列名以渲染脚本为准，全量进 Excel。主报告不退回成只有一句话。集团一个集团一行，只展示 Top 10，不合并。国家一国一行，最多 10 个，不合并。城市一城一行，只展示 Top 15，不合并。资源优势方合成一张表，只列达标资源。某一类没有达标资源，表里就不出现这一类。其他供应商占比写名称和该资源内的 TTV 占比，最多 5 个，用中文逗号分隔；没有其他供应商写「无」。国家内品牌的资源写成「国家 · 集团」。Independent 不进入品牌优势和国家内品牌优势。

`.summary` 一句，覆盖地域、品牌、星级里各自最大的那一项。

## 客户

无权限则整章不出现，导轨也不留入口。客户查询带 `supplier_rebook_sequence = 1`。

Client Top 15、Parent Top 15。Client 表的列是 Client ID、Parent Client ID、有产酒店、BKS、TTV、ADR、BKS 占比、TTV 占比。Parent 表的列是 Parent Client ID、有产酒店、BKS、TTV、ADR、BKS 占比、TTV 占比，表注写 CR5、CR10。

`.summary` 三行：走量型、走利型、集中度。没有符合规则的类型就写「Top 15 里没有走量型」或「没有走利型」，不编一个。

## 预订模式

餐型、入住晚数、提前天数。餐型列：餐型、BKS、TTV、ADR、TTV 占比。后两张列：区间、BKS、TTV、BKS 占比、TTV 占比。都按 TTV 降序。

餐型显示名：`1` 仅客房、`2` 含早餐、`3` 半食宿、`4` 全食宿、`5` 全包、`6` 含晚餐、`7` 早加晚、`8` 早加午、`9` 含午餐、`10` 午加晚、`11` 午或晚、`12` 早加午或晚。空为「（餐型为空）」。显示名后面可以留原编号。

`.summary` 一句，点出 TTV 最高的餐型、BKS 最高的晚数、TTV 最高的提前天数。

## 脚注

HTML 不设数据附件节，左侧导轨也不留入口。Excel 仍要生成，路径写在对话里。脚注写四句来源：产量视图、客户表、技术指标视图、L2L 配置表，以及本次用的三个阈值。
